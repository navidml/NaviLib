# نتیجهٔ بررسی و بازسازی NaviLib

## ارزیابی کلی

نگه‌داشتن این کتابخانه ارزش دارد. کد اولیه از قبل قابلیت‌های متنوعی در پاک‌سازی، تحلیل، مهندسی ویژگی و ارزیابی داشت؛ نقطهٔ ضعف اصلی، نبود تست و بسته‌بندی کامل، مستندات پراکنده و چند خطای رفتاری بود. اضافه‌کردن الگوریتم بیشتر بدون اصلاح این پایه، اعتمادپذیری کتابخانه را بهتر نمی‌کرد.

**بخش `modeling` نگه داشته شد.** این بخش یک فایل است، نه یک پوشهٔ مستقل. پایپ‌لاین، اعتبارسنجی گروهی و تودرتو، مقایسه با مدل پایه و نگهداری مدل همراه پیش‌پردازش برای کار دانشمند داده کاربردی‌اند. قرارگرفتن پیش‌پردازش یادگرفتنی داخل اعتبارسنجی نیز با [راهنمای رسمی scikit-learn دربارهٔ نشت اطلاعات](https://scikit-learn.org/stable/common_pitfalls.html) هم‌راستاست.

## تغییرات انجام‌شده

| بخش | تغییر و نتیجه |
|---|---|
| نصب | افزودن `pyproject.toml`، وابستگی‌های اصلی و اختیاری و نسخهٔ واحد `0.5.0` |
| نام‌گذاری | نام‌های توصیفی مانند `impute_missing`، `scale_features` و `cross_validate_model`؛ حفظ نام‌های قبلی به‌صورت alias |
| راهنما | تکمیل بخش پارامترها و خروجی توابع عمومی، مرجع API تولیدشده از کد و راهنمای فارسی |
| کشف قابلیت‌ها | `help_map(query)` با امضای تابع، توضیح، ماژول و نام جایگزین |
| ظاهر | سه تم روشن، تیره و چاپ؛ پالت سفارشی، اندازهٔ نوشته و تنظیمات محلی نمودار |
| گزارش | `create_report` و `DataReport` با HTML مستقل، جدول‌های قابل استفاده و شکل‌های ذخیره‌پذیر |
| کیفیت | `audit_data` با پیشنهاد اقدام برای گمشده‌ها، بی‌نهایت، تکرار، ثابت، فاصلهٔ اضافی، رشتهٔ عددی و کپی هدف |
| قرارداد داده | `infer_schema` و `validate_schema` برای تغییر نوع، ستون گمشده/اضافی، null جدید و دستهٔ ناشناخته |
| زمان | تقسیم زمانی با gap، lag گروهی و ویژگی پنجره‌ای با حذف مشاهدهٔ جاری از محاسبه |
| آمار | اصلاح Lilliefors، درجات آزادی همبستگی جزئی، ورودی نسبتی خی‌دو و افزودن اصلاح آزمون‌های متعدد |
| نگهداری | تست‌های اجرایی، مثال مستقل، ساخت wheel/sdist و پیکربندی CI |

## ایرادهای مهم اصلاح‌شده

- بازاجرای پیش‌پردازش در حالت strict دیگر نبود ستون مورد نیاز را در بعضی مراحل پنهان نمی‌کند.
- `ChainTransformer` ستون هدف را از مراحل غیرنظارتی دور نگه می‌دارد و تغییر تعداد/ترتیب ردیف‌ها را رد می‌کند.
- مدل‌های دورهای اعتبارسنجی برای OOF دوباره آموزش داده نمی‌شوند؛ همان مدل‌های آموزش‌دیده و همان تقسیم‌ها استفاده می‌شوند.
- اعتبارسنجی تودرتو، گروه‌ها را در دورهای داخلی نیز جدا نگه می‌دارد.
- مرتب‌سازی معیارهای خطای سفارشی بر اساس جهت درست معیار انجام می‌شود.
- آستانهٔ صفر حفظ می‌شود؛ شیوع ثبت‌شده مربوط به کلاس مثبت احتمال است، نه لزوماً کلاس اقلیت.
- کلاس مثبت پیش‌فرض ارزیابی با ترتیب کلاس‌های scikit-learn هماهنگ است؛ انتخاب صریح کلاس مثبت برای ماتریس احتمال هم اعمال می‌شود.
- `predict_model` خروجی `load_model` را مستقیماً می‌پذیرد و state جداگانهٔ ذخیره‌شده را بازاجرا می‌کند.
- نام ویژگی‌های توضیح مدل پس از گسترش ستون‌ها در پایپ‌لاین درست استخراج می‌شود.
- WOE با دادهٔ ناکافی به کدگذاری نشت‌دارِ درون‌نمونه‌ای برنمی‌گردد.
- نوع خروجی count encoding میان fit و replay یکسان شده است.
- اعداد صحیح nullable با میانهٔ اعشاری و دسته‌های خالی با مقدار جایگزین جدید قابل پردازش‌اند.
- جای‌گذاری تکرارشونده روی دادهٔ یکسان، نتیجهٔ قابل بازتولید می‌دهد.
- نام‌های فارسی حفظ می‌شوند و نام‌های تکراری حتی در حضور پسوندهای موجود، یکتا می‌شوند.
- SMAPE سهم صفر/صفر را صفر حساب می‌کند؛ وزن نمونه در خطاهای رگرسیون، baseline و bootstrap مربوط اعمال می‌شود.
- آزمون KS با پارامترهای نرمال تخمین‌زده‌شده از همان نمونه، از [تصحیح Lilliefors](https://www.statsmodels.org/stable/generated/statsmodels.stats.diagnostic.lilliefors.html) استفاده می‌کند.

## اعتبارسنجی انجام‌شده

۶۹ تست روی Windows و Python 3.11.9 با NumPy 2.4.6، pandas 3.0.5، scikit-learn 1.9.1، SciPy 1.17.1 و matplotlib 3.11.2 اجرا و موفق شدند. این تست‌ها خانواده‌های تبدیل عددی، مقیاس‌بندی، کدگذاری، بازه‌بندی، جای‌گذاری، ویژگی‌های مشتق‌شده، ذخیره/بارگذاری، مدل‌سازی، احتمال‌ها، کیفیت، زمان، آمار و تم‌ها را پوشش می‌دهند. SMOTE و پایپ‌لاین توازن با imbalanced-learn 0.14.2 نیز آزمایش شدند.

مثال کامل روی دادهٔ ساختگی اجرا شد؛ نمودارهای نمونه از نظر خوانایی بررسی شدند. نصب editable، بررسی وابستگی‌ها و ساخت wheel و sdist موفق بود. فایل CI برای چند نسخهٔ Python روی Windows و Linux آماده است؛ اجرای راه‌دور CI در این نشست انجام نشده است.

## حدود نسخهٔ فعلی

این نسخه یک جعبه‌ابزار کاربردی برای دادهٔ جدولی است؛ کامل‌بودن برای تمام مسائل داده، یا درستی همهٔ ترکیب‌های ممکن پارامترها ادعا نمی‌شود. SHAP و موتورهای اختیاری Excel/Parquet در این نشست اجرا نشده‌اند. پشتیبانی حداقل نسخه‌های وابستگی‌ها در همین نشست جداگانه آزموده نشده است.

انتخاب خودکار نوع مسئله ابتکاری است. target/WOE encoding از دورهای تصادفی داخلی استفاده می‌کند؛ برای دادهٔ زمانی یا چند مشاهده از یک موجودیت باید طراحی ویژهٔ پیش‌پردازش داشته باشید. ویژگی پنجره‌ای فقط وقتی قابل استفاده است که مقادیر تاریخیِ ورودی واقعاً در زمان پیش‌بینی در دسترس باشند.

معیارهای Pearson/Spearman و بیشینهٔ خطا در گزارش رگرسیون ذاتاً در این پیاده‌سازی وزن‌دار نیستند؛ وزن‌دهیِ خطاها و فاصله‌های اطمینان در راهنمای پارامتر مشخص شده است. گزارش‌های کیفیت، هشدار و پیشنهاد می‌دهند و به‌طور خودکار ستون را حذف یا نوع آن را تبدیل نمی‌کنند. داده‌های تو‌در‌تو مانند list/dict در سلول‌ها باید پیش از تحلیل جدولی عادی‌سازی شوند.

فایل مدل‌های قدیمی همچنان به سازگاری نسخه‌های کتابخانه‌های زیربنایی وابسته است. برای پروژه‌های جدید، استفاده از نام‌های استاندارد و نگهداری نسخهٔ وابستگی‌ها همراه مدل توصیه می‌شود. در این نشست commit یا انتشار روی PyPI انجام نشده است؛ فقط تغییر نام فایل آماری برای حفظ صحیح حروف آن در Git stage شده است.
